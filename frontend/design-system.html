1 · Buttons — all states

Always native <button> + a .btn-* class — never <wa-button> (ADR 0011). Hover/active: subtle surface change, no transform. Focus: 2px --brand-blue ring, offset 2–3px (tab or shift+tab to see focus states — focus-visible only shows via keyboard).

Primary pills

.btn-ink — default
:disabled — 0.4 opacity (per-class)
[data-loading] — width-pinned, aria-busy

Secondary · escalation · link

.btn-outline — hairline border, transparent
.btn-blue — the city-lane action

Link-styled button

.btn-link — real <button> that reads as a text link. For in-page state switches only ("links navigate, buttons act") — if it navigates, use a real <a>. Default color is quiet text; override color in the call site's scope when it sits on a colored line.
.btn-link:disabled — faint, not-allowed cursor

Compact (in-card action rows)

.btn-*-sm — 38px min-height, 0.9rem, nowrap

Dark mode

Dark mode is a root-level token swap (html.wa-dark in tokens.css — light/dark are page states, not subtree states). Use the Toggle dark mode button in the toolbar above to flip this whole page and inspect every example in both themes — the token table in section 3 also shows the light and dark hexes side by side. The pill inversion to check for: --ink becomes light (#ededed) with a dark label (--on-ink #131313) — light-on-light or dark-on-dark pills are Figma errors, not theme quirks.

Full-width (per-screen choice, e.g. setup scopes it)

Width is a per-screen choice (e.g. .setup .btn-ink { width: 100% }) — never global.

2 · Where we differ from off-the-shelf Web Awesome

We adopt WA for form controls, icons, spinners, badges, callouts — but with deliberate divergences. Theme base: wa-theme-default + wa-palette-default + wa-brand-blue, matching the official Web Awesome Figma kit.

Concern Off-the-shelf Web Awesome Our choice Why
Buttons <wa-button> component Native <button> + .btn-* classes One vocabulary; wa-button's stateful features (loading/variants) were unused; ::part() override tax (ADR 0011)
Primary color Default palette brand blue #0053c0 (brand-40) App accent --brand-blue: #155fce Deliberately distinct — WA controls keep their tint; our UI uses ours. Don't average them.
Primary CTA look Variants × appearances (accent/filled/outlined…) Charcoal ink pill (--ink/--on-ink) The design's CTA; inverts light↔dark. Blue is reserved for the 311 lane only.
Hover behavior Default theme: no hover transform; subtle active scale Our buttons: subtle background change only Calm municipal tone; no additional motion override is needed
Button radius --wa-border-radius-m = 6px (theme scale 1) Full pill (--radius-pill: 999px) Signature look of every .btn-* pill
Focus ring brand-60 ring, 0.1875rem wide, offset ~1px 2px --brand-blue, offset 2–3px, :focus-visible only Matches the app's own interactive color; keyboard-only (never on mouse click)
Loading state <wa-button loading> (spinner + width pin) button[data-loading] pattern: inline wa-spinner, JS pins --btn-loading-min-width, sets aria-busy + disabled We own it now that wa-button is gone — see the demo in section 1
Native control skinning native.css skins every bare input/button/textarea We style bare controls ourselves (.login__field input, .typed-evidence textarea, …) Kept native.css (audited 2026-09-14); removal queued with a replacement checklist

4 · Non-negotiable rules

Tokens only No raw hex/rgb in component CSS — dark mode stays correct by construction.
Color never carries meaning alone Severity/status always pairs with a text label + icon (WCAG 1.4.1). Hazard red ships with "Hazard"; amber ships with "You marked this as…".
44px minimum touch targets All interactive elements (WCAG 2.2 AA, 2.5.8). Compact buttons are 38px visual but sit in 44px rows or get padded wrappers.
Focus is keyboard-only :focus-visible with 2px brand-blue ring, 2–3px offset. Never remove outlines without a replacement.
CSS over JS Never do in JavaScript what CSS can do — especially animation. CSS animations/transitions are less code, GPU-composited, respect prefers-reduced-motion in one media query, and can't leak timers. Established patterns: @starting-style + transition-behavior: allow-discrete for dialog open/close (the sheets), @keyframes (the assessment progress bar), state classes toggled by JS but animated by CSS.
