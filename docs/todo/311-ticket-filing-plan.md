# 311 ticket filing app action plan

Status: implemented

## Goal

When a guidance rule has a 311 app action, the backend files the corresponding
311 service request in SF's HUB/Verint system either silently at task creation
or explicitly when the field user taps `File 311 ticket`, depending on the rule
outcome and app-action trigger.

## Source contracts

- HUB CreateSR uses Basic Authentication in the dev environment.
- CreateSR field names should match the HUB documentation exactly.
- `ToHubDate` is generated by HUB on receipt and should not be sent by this app.
- `ResponsibleAgency` is populated from the rulebase `Responsible agency code`
  column. If the column is `'-'`, send the field blank.
- The HUB agency lookup endpoint remains available as a compatibility fallback
  for legacy app actions that do not carry a responsible agency code:
  `https://oicdev-axallnoytkrb-px.integration.us-phoenix-1.ocp.oraclecloud.com/ic/api/integration/v1/flows/rest/HUBWEB/1.0/lookup_agency_table`
- The rulebase column `311 service code or action` contains either:
  - a concrete service code to send as `NatureofRequest`, or
  - an analysis command such as `Run graffiti analysis` or
    `Run bulky item analysis`.
- The rulebase `THEN...` column supports:
  - `Action`
  - `Escalation`
  - `Non-Actionable Escalation`

## CreateSR payload

For each filed 311 ticket, build:

```json
{
  "SourceAgency": "76",
  "SourceRequestID": "<task/service-code idempotency key>",
  "SourceAgencyReceiveDate": "YYYY-MM-DDTHH:mm:ss",
  "ResponsibleAgency": "<resolved agency id>",
  "NatureofRequest": "<service code>",
  "ProblemDescription": "<assessment condition description>",
  "Latitude": "<latitude>",
  "Longitude": "<longitude>"
}
```

`ProblemDescription` must be 2000 characters or fewer.
`SourceRequestID` must be 50 characters or fewer.

## Location resolution

Use location in this order:

1. Assessment/condition metadata already stored with the condition.
2. The site's default location from `SITE#<siteId> / #META`.
3. If neither exists, fail the app action with a retryable `missing_location`
   result.

For dev/test bootstrap, add:

- provider `the-gubbio-project`, name `The Gubbio Project`
- site `st-john-the-evangelist`, name `St. John the Evangelist`
- site default location:
  - latitude `37.76656393517443`
  - longitude `-122.4213267021692`
- associate the site with the provider
- point the active local/dev site code at this site

## Rulebase ingestion

Replace the current generated guidance catalog with the updated CSV rulebase.
Continue using:

- rule ID
- evaluation order
- severity range
- ask user
- user response conditions
- then action/escalation kind
- action/escalation text
- user-facing button label
- app action

Add support for:

- `311 service code` / `311 service code or action`
- `Responsible agency code`

Normalize:

- `Create and file 311 ticket` and
  `Create and file 311 ticket on user's behalf using API` to
  `create_311_ticket`
- `File 311 ticket on action creation` and
  `File 311 ticket on escalation creation` to a `create_311_ticket` app action
  with `executionTrigger: "task_created"`
- `Create and file 311 ticket on confirmation` to a `create_311_ticket` app
  action with `executionTrigger: "user_confirmed"`
- legacy `Route to phone app` values to tracked manual actions, not phone-app
  routes
- empty markers such as `'-'` to empty values

## Outcome behavior

- `Action`: create the task/action item, silently execute task-created 311 app
  actions, and record the result on the task. The user sees the normal action
  completion button, not a 311 filing button.
- `Escalation`: create the task and wait for explicit user confirmation through
  the `File 311 ticket` button before filing.
- `Non-Actionable Escalation`: create the escalation item, silently execute
  task-created 311 app actions, and record the result on the task. The user sees
  the rulebase completion button, not a 311 filing button.

## Analysis-command service code resolution

If the rulebase supplies a direct service code, use it as `NatureofRequest`.

If the rulebase supplies `Run bulky item analysis`, call:

```text
POST /v1/classifiers/bulky-items
```

If the rulebase supplies `Run graffiti analysis`, call:

```text
POST /v1/classifiers/graffiti
```

Use the existing Street Conditions Analysis API base URL and API key. Classifier
requests contain one image:

```json
{
  "image": {
    "content_type": "image/jpeg",
    "base64": "..."
  },
  "caller": {
    "request_id": "<task id>"
  }
}
```

Map every returned classifier label to a 311 service code. If the classifier
returns more than one service code, file one CreateSR ticket per code.

Store the shared classifier label mapping in
`backend/src/integrations/sf311-classifier-service-code-map.js`, with
`SF311_CLASSIFIER_SERVICE_CODE_MAP` reserved as an optional JSON override for
urgent taxonomy corrections.

## Idempotency

Task completion already claims a task with a short `completing` lease. Preserve
that behavior and add app-action idempotency:

- before filing, check existing `appActionResults` for submitted 311 results
- use deterministic `SourceRequestID` values per task/service code
- do not create duplicate tickets when a completion retry observes existing
  submitted results

## Secrets and config

Add configuration:

- `GNP_311_SUBMISSION_ENABLED`
- `SF311_CREATESR_URL`
- `SF311_AGENCY_LOOKUP_URL`
- `SF311_BASIC_AUTH_SECRET_ARN`
- optional `SF311_CLASSIFIER_SERVICE_CODE_MAP` JSON override

Store the dev Basic Auth credentials as a Secrets Manager JSON value. Do not put
the secret value in Terraform state or source control. The provided dev
credentials are temporary test credentials and should be rotated before launch.

## Frontend behavior

The field app keeps the existing explicit user button. For user-confirmed
`create_311_ticket`, the button should read from the rulebase label and call
task completion.

The app does not route to phone numbers or render `tel:` links. Call-related
rules are non-actionable escalations: the user sees the rulebase completion
button, such as `We called 911`, and the app records whether they did the thing.
